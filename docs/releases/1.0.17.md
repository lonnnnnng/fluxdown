## 本次改动

- 修复 Windows 桌面 EXE 被链接为 Console 子系统的问题：Release 改为 GUI 子系统，启动应用不再同时出现命令行窗口，关闭控制台不会连带终止桌面应用。
- Windows Debug 构建继续保留控制台日志；`fluxdown.exe` CLI 继续使用 Console 子系统，命令行输出、脚本调用和退出码行为不变。
- Windows 启动时对可选 ed2k 后端执行的版本探测使用 `CREATE_NO_WINDOW`，避免后台探测控制台工具时短暂闪窗。
- 发布验证读取真实 PE32/PE32+ 文件头：桌面程序必须为 GUI 子系统，CLI 必须为 Console 子系统。旧版 `1.0.16` 桌面 EXE 已被新门禁按预期拒绝。

## 验证与边界

- 本地 Core 与桌面 Rust 测试 110 项通过，7 项需要外部协议环境的用例按原配置忽略；发布策略与 PE 文件头回归 21 项通过。
- `1.0.16` 正式 Windows 桌面 EXE 已核验为错误的 `Subsystem=3`，安装器哈希与 Release 附件一致，确认不是用户拿错安装包。
- 本版必须以 Windows CI 新构建的实际 EXE 通过 `Subsystem=2` 门禁为发布前提。静态门禁不能替代用户桌面上的前台交互测试。
- macOS DMG 仍是标准 App Bundle；Linux DEB/RPM 的 `.desktop` 仍为 `Terminal=false`，本次修复不改变另外两个桌面平台。
- 当前未配置完整发行签名 secrets：Android APK 可能使用测试签名，Windows 可能未做 Authenticode，macOS 为 ad-hoc；iOS 不提供普通用户可安装包。
